| 类型                 | 注入位置                            | 数据库支持                       | 主要用途              |
| :----------------- | :------------------------------ | :-------------------------- | :---------------- |
| **Optimizer Hint** | `SELECT * /*+ hint */ FROM ...` | MySQL 8、MariaDB、Oracle、TiDB | 干预优化器执行计划         |
| **Index Hint**     | `FROM users USE INDEX (idx)`    | MySQL、MariaDB、TiDB          | 强制/建议/忽略索引        |
| **Comment Hint**   | SQL 任意位置                        | 全部数据库                       | SQL 打标（监控、读写分离路由） |
## 1. Optimizer Hints 干预执行计划
```go
import "gorm.io/hints"

// 限制查询最大执行时间 1 秒，超时自动杀掉（防止慢查询拖垮库）
db.Clauses(hints.New("MAX_EXECUTION_TIME(1000)")).Find(&users)

// 提示优化器：后面要 ORDER BY，建临时表时保留索引
db.Clauses(hints.New("SET_VAR(optimizer_switch='use_index_extensions=on')")).Find(&users)
```
>[!attention]
>语法高度数据库相关
> MySQL : ` MAX_EXECUTION_TIME` 
>PostgreSQL :  `SET LOCAL statement_timeout`
>Oracle ： `/*+ FIRST_ROWS(10) */`
>跨库代码要写适配层

# 2. Index Hints 索引控制
MySQL系的 `USE INDEX / FORCE INDEX / IGNORE INDEX` 语法，GORM 做了类型安全封装：
```go
// 建议优化器使用某个索引（优化器可以不听）
db.Clauses(hints.UseIndex("idx_user_name")).Find(&User{})
// SELECT * FROM `users` USE INDEX (`idx_user_name`)

// 强制使用索引（优化器必须听）
db.Clauses(hints.ForceIndex("idx_user_name", "idx_user_id").ForJoin()).Find(&User{})
// SELECT * FROM `users` FORCE INDEX FOR JOIN (`idx_user_name`,`idx_user_id`)

// 忽略索引
db.Clauses(hints.IgnoreIndex("idx_user_name").ForGroupBy()).Find(&User{})
// SELECT * FROM `users` IGNORE INDEX FOR GROUP BY (`idx_user_name`)

// 组合：不同用途不同索引
db.Clauses(
    hints.ForceIndex("idx_user_name", "idx_user_id").ForOrderBy(),
    hints.IgnoreIndex("idx_user_name").ForGroupBy(),
).Find(&User{})
// FORCE INDEX FOR ORDER BY (...) IGNORE INDEX FOR GROUP BY (...)
```

>[!attention]
**`.ForJoin() / .ForOrderBy() / .ForGroupBy()`** 对应 MySQL 的作用域修饰，限定 hint 只对 JOIN/ORDER BY/GROUP BY 生效，不加则对整个查询生效
# 3. Comment Hints  SQL 打标

在不同位置注入注释，对执行无影响，但对运维极有价值
```go
// SELECT 关键字后
db.Clauses(hints.Comment("select", "master")).Find(&User{})
// SELECT /*master*/ * FROM `users`
// 常用于读写分离中间件（如 ShardingSphere）路由：/*master*/ 表示走主库

// 语句最前面（INSERT 之前）
db.Clauses(hints.CommentBefore("insert", "node2")).Create(&user)
// /*node2*/ INSERT INTO `users` ...

// 语句末尾
db.Clauses(hints.CommentAfter("where", "hint")).Find(&User{}, "id = ?", 1)
// SELECT * FROM `users` WHERE id = ? /* hint */
```

- 读写分离路由
```go
// 中间件识别到 /*master*/ 注释，强制路由到主库
func GetUserForUpdate(db *gorm.DB, id uint) (*User, error) {
    var user User
    err := db.Clauses(hints.Comment("select", "master")).
        Clauses(hints.UseIndex("PRIMARY")).  // 顺便锁行
        First(&user, id).Error
    return &user, err
}
```

 - 慢日志归因
```go
// 慢查询日志里能直接看到是哪个业务模块发的 SQL
db.Clauses(hints.CommentAfter("where", "order-service:QueryPendingList")).
    Where("status = ? AND created_at > ?", "pending", yesterday).
    Find(&orders)
```
DBA 看到慢日志里的注释，直接定位到 `order-service` 的 `QueryPendingList`，不用反向排查。
