# 1. 标签语法详解

```plain
`gorm:"index:索引名,选项1,选项2"`
```
**位置 1：索引名**（可省略，使用 GORM 自动列命名）
>[!attention] gorm:"index: ,选项1,选项2"
>不自行命名第一个字段要用逗号空出来


**位置 2 起：选项**，常用选项：

| 选项           | 说明          | 示例                                         |
| :----------- | :---------- | :----------------------------------------- |
| `unique`     | 唯一索引        | `index:idx_name,unique`                    |
| `class`      | 索引类型        | `class:FULLTEXT`、`class:SPATIAL`（默认 BTREE） |
| `type`       | 索引方法        | `type:btree`（PG 可写 `gin`、`gist`）           |
| `sort`       | 排序方向        | `sort:desc/asc`，升序/降序                      |
| `collate`    | 排序规则        | `collate:utf8mb4_unicode_ci`               |
| `length`     | 前缀长度        | `length:10`（长字段建前缀索引）                      |
| `where`      | 部分索引条件      | `where:age > 10`（PG 部分索引、MySQL 不适用）        |
| `expression` | 表达式索引       | `expression:ABS(age)`（函数索引）                |
| `comment`    | 索引注释        | `comment:hello \, world`（逗号要转义）            |
| `priority`   | 复合索引列顺序     | `priority:1`（默认 10，数值小在前）,会影响查询时是否走索引      |
| `option`     | 数据库原生选项     | `option:CONCURRENTLY`（PG）                  |
| `composite`  | 嵌入结构共享索引 ID | `composite:myname`                         |

**示例**：
```go
Age int64 `gorm:"index:,class:FULLTEXT,comment:hello,where:age > 10"`
// CREATE FULLTEXT INDEX `idx_users_age` ON `users`(age) COMMENT 'hello'
```

# 2.  唯一索引
```go
Email string `gorm:"uniqueIndex"`
// 等效于 index:,unique

// 命名 + 排序
Phone string `gorm:"uniqueIndex:idx_phone,sort:desc"`
```

复合唯一索引要在每个字段上都写 ,unique，不能只写一个：
```go
//  错误：只有 Name 声明了 unique
type User struct {
    Name   string `gorm:"index:idx_member,unique"`
    Number string `gorm:"index:idx_member"`
}
// 正确：两个字段都写
type User struct {
    Name   string `gorm:"index:idx_member,unique"`
    Number string `gorm:"index:idx_member,unique"`
}
```

# 3. 复合索引

**两个字段同名索引 = 复合索引**，列顺序默认按 struct 字段顺序：
```go
type User struct {
    Name   string `gorm:"index:idx_member"`
    Number string `gorm:"index:idx_member"`
}
// CREATE INDEX idx_member ON users(name, number)

// 用 priority 调整顺序（数值小的在前）
type User struct {
    Name   string `gorm:"index:idx_member,priority:2"`
    Number string `gorm:"index:idx_member,priority:1"`
}
// 索引变为 (number, name)



```
>[!attention]
列顺序遵循最左前缀原则
设计原则：把区分度高的、查询中最常单独作为条件的列放前面。



# 4. 嵌入结构共享复合索引

问题场景：
```go
type Base struct {
    TenantID uint `gorm:"index:idx_tenant_name"`  
    Name     string `gorm:"index:idx_tenant_name"`
}
type User struct { Base }  // 想要 idx_users_xxx
type Order struct { Base } // 想要 idx_orders_xxx
```

```go
//composite作为索引 ID，让 GORM 按命名策略自动生成表级唯一名
type Base struct {
    TenantID uint   `gorm:"index:,unique,composite:tenant_name"`
    Name     string `gorm:"index:,unique,composite:tenant_name"`
}
type User struct {
    Base
}
// CREATE UNIQUE INDEX idx_users_tenant_name ON users(tenant_id, name)

type Order struct {
    Base
}
// CREATE UNIQUE INDEX idx_orders_tenant_name ON orders(tenant_id, name)
```

# 5. 字段多索引

```go
type UserIndex struct {
    OID          int64  `gorm:"index:idx_id;index:idx_oid,unique"`
    MemberNumber string `gorm:"index:idx_id"`
}
// 生成：
// INDEX idx_id (member_number, oid)       —— 复合索引
// UNIQUE INDEX idx_oid (oid)              —— 单列唯一索引
```
>[!attenion]
用分号 ; 分隔多个索引声明。
