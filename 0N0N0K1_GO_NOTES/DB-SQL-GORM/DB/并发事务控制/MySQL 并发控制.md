# 1. MVCC
>[!tip] MVCC依赖隐藏字段 + undo log版本链 + 读视图ReadView
### 隐藏字段

- **DB_TRX_ID**：创建或最后修改该行的事务 ID
- **DB_ROLL_PTR**：指向旧版本数据的回滚指针（存储于 Undo Log）
- **DB_ROW_ID**：隐含主键（无显式主键时自动生成）
### undo log版本链

- **undo log**：是物理日志，记录数据的历史版本（如 DELETE 前的旧值、UPDATE 后的原值），用于事务回滚和 MVCC。
    - **Insert Undo Log**：记录插入操作的反向操作（仅在回滚时使用，提交后可删除）
    - **Update/Delete Undo Log**：记录修改前的旧版本，用于 MVCC 的版本链维护

- **版本链**：是逻辑概念，通过 undo log 将同一行数据的多个版本串联起来，形成链表结构，供 MVCC 读取历史版本。

- **Purge 线程**：定期清理过期版本（`delete_trx_id < 全局最小活跃事务ID`），释放存储空间

### 读视图ReadView 

视图/快照中包含四个关键字段:
1. M_IDs: 创建视图/快照时所有活跃事务（开启未提交）的ID集合 
2. MIN_TRX_ID: 创建视图/快照时事务集中最小的事务ID
3. MAX_TRX_ID: 创建视图/快照时事务集中最大的事务ID+1
4. CREATE_TRX_ID:  创建视图/快照的事务自己的ID

### 可见性判断规则
    从当前版本开始向 undo log 里旧版本逐个进行判断
    根本原则：TRX_ID已提交/自身操作为可见，未提交不可见

可见：
1. TRX_ID = CREATE_TRX_ID
2. TRX_ID < MIN_TRX_ID
3. MIN_TRX_ID <= TRX_ID < MAX_TRX_ID  &  TRX_ID 不在 M_IDs 中

不可见：
1. TRX_ID >= MAX_TRX_ID
2. MIN_TRX_ID <= TRX_ID < MAX_TRX_ID  &  TRX_ID 在 M_IDs 中

### 当前读/快照读

- 快照读（Snapshot Read）：  
    ==普通`SELECT`语句默认使用快照读==，通过`undo log`版本链和 ReadView 生成一致性视图，无需加锁即可实现非阻塞读（Read View 生成与隔离级别有关）

- 当前读（Current Read）：  
    ==`SELECT ... FOR UPDATE`或写操作使用当前读==，直接读取最新数据并==加锁==，防止并发修改。例如：
```sql
    SELECT * FROM table WHERE id=1 FOR UPDATE; ---- 加行级排他锁（X锁）
```
### 隔离级别

| 隔离级别                                  | 脏读  | 不可重复读 | 幻读  | 隔离性 | 并发性 | 说明                             |
| ------------------------------------- | --- | ----- | --- | --- | --- | ------------------------------ |
| 串行化（SERIALIZABLE）                     | 无   | 无     | 无   | 最高  | 最低  | 完全串行化的读，每次读都需要获得表级共享锁，读写相互都会阻塞 |
| 可重复读（REPEATABLE READ）(==InnoDB默认级别==) | 无   | 无     | 有   |     |     | 在第一次读取时生成读视图，后续依照该视图读取<br>     |
| 读已提交（READ COMMITTED）                  | 无   | 有     | 有   |     |     | 每次读取时生成读视图，后续依照该视图读取           |
| 读未提交（READ UNCOMMITTED）                | 有   | 有     | 有   | 最低  | 最高  | 始终读取最新行版本，不管对应事务是否提交           |

# 2. 锁机制

InnoDB 的锁分两大维度:
**锁粒度**(行锁/表锁/间隙锁)和**锁模式**(共享S/排他X)
```plain
全局锁 ──── 整个数据库
表级锁 ──── 整个表
  ├── MDL / 意向锁 / 自增锁：是「辅助锁」而非数据锁
  └── 表读锁 / 表写锁：直接锁数据
页级锁 ──── 数据页（InnoDB 内部）
行级锁 ──── 单条索引记录（精确控制，并发最高）
```
**使用趋势**：MyISAM 时代主要用表锁；InnoDB 默认使用行锁（配合 MVCC），表锁退化为 DDL 保护（MDL）和意向标记。**==锁粒度越小，并发性能越好，但加锁/解锁开销也越大。**==

## 1. 全局锁（Global Lock）

| 锁                                      | 触发条件                                              | 作用                         |
| :------------------------------------- | :------------------------------------------------ | :------------------------- |
| **Flush tables with read lock（FTWRL）** | ==手动==执行 `FLUSH TABLES WITH READ LOCK`（常用于全库逻辑备份） | 对整个数据库加只读锁，禁止所有库的写操作和 DDL  |
| **Backup Lock**                        | MySQL 8.0 引入的 `LOCK INSTANCE FOR BACKUP`          | 备份时允许写入但禁止 DDL，比 FTWRL 更轻量 |

## 2. 表级锁（Table Lock）

| 锁                           | 触发条件                                             | 作用                               |
| :-------------------------- | :----------------------------------------------- | :------------------------------- |
| **表读锁（Table Read Lock）**    | ==手动== `LOCK TABLES t READ`                      | 持有者可读，他人可读不可写                    |
| **表写锁（Table Write Lock）**   | ==手动== `LOCK TABLES t WRITE`                     | 持有者独占读写，他人完全不可访问                 |
| **元数据锁 MDL（Metadata Lock）** | ==每次访问表自动加（读 MDL：增删改查；写 MDL：DDL 如 ALTER TABLE）== | 保证表结构变更与查询/写入互斥；写 MDL 是阻塞的，有排队队列 |
| **意向锁（Intention Lock）**     | ==加行锁前自动加（IX 意向排他锁 / IS 意向共享锁）==                 | 标记该表中有行锁，避免逐行检查，快速判断表级锁与行锁是否冲突   |
| **自增锁（AUTO-INC Lock）**      | ==向含 AUTO_INCREMENT 的表插入时==                      | 保证自增列值唯一                         |

|                             | IS                                               | IX                               | 表读锁  | 表写锁 |
| :-------------------------- | :----------------------------------------------- | :------------------------------- | ---- | --- |
| **IS**                      | ✅ 兼容                                             | ✅ 兼容                             | ✅ 兼容 | ❌   |
| **IX**                      | ✅ 兼容                                             | ✅ 兼容                             | ❌    | ❌   |
| **表读锁**                     | ✅ 兼容                                             | ❌                                | ✅ 兼容 | ❌   |
| **表写锁**                     | ❌                                                | ❌                                | ❌    | ❌   |
## 3. 页级锁（Page Lock）

| 锁      | 触发条件                   | 作用                         |
| :----- | :--------------------- | :------------------------- |
| **页锁** | InnoDB 内部实现，一般不显式暴露给用户 | 锁定一整页（数据页/索引页）数据，介于表锁与行锁之间 |

## 4. 行级锁（Row Lock，InnoDB）

- 加行锁前自动加IX 意向排他锁 / IS 意向共享锁
- **不加锁**：普通 `SELECT`（快照读）
- **加行锁**：`FOR UPDATE` / `FOR SHARE` / DML，RR 下可能是记录锁、间隙锁、临键锁的组合
- **永远有 MDL**：任何语句都有元数据锁，DDL 要小心

| 锁                                | 触发条件                                             | 作用                                    |
| :------------------------------- | :----------------------------------------------- | :------------------------------------ |
| **记录锁（Record Lock）**             | ==SELECT ... FOR UPDATE / FOR SHARE 命中唯一索引等值查询== | 锁住索引上的单条记录                            |
| **间隙锁（Gap Lock）**                | ==RR 隔离级别下非唯一索引、范围查询时==                          | 锁住索引记录之间的间隙，防止幻读                      |
| **临键锁（Next-Key Lock）**           | ==RR 隔离级别下普通 SELECT 或范围更新时==                     | 记录锁 + 间隙锁的组合，锁住记录及前面的间隙:  （前一个记录，该记录] |
| **插入意向锁（Insert Intention Lock）** | ==向间隙中插入新记录==                                    | 表明插入意图，与间隙锁互斥，避免插入幻读                  |

| 锁类型   | RC 级别 | RR 级别 |
| :---- | :---- | :---- |
| 记录锁   | ✅     | ✅     |
| 间隙锁   | ❌     | ✅     |
| 临键锁   | ❌     | ✅     |
| 插入意向锁 | ✅     | ✅     |

### 1. 记录锁（Record Lock）

| 加锁条件                     | 说明                    |
| :----------------------- | :-------------------- |
| 唯一索引等值查询，且记录**存在**       | 对该条记录加记录锁             |
| `UPDATE / DELETE` 命中唯一索引 | 记录锁                   |
| `INSERT`                 | 对新记录加隐式锁（插入意向锁 + 记录锁） |
### 2. 间隙锁（Gap Lock）

| 加锁条件                  | 说明            |
| :-------------------- | :------------ |
| 唯一/普通索引等值查询，记录**不存在** | 锁表中记录逻辑上所处的间隙 |
RR 下即使查询未命中记录，也会锁住记录两侧间隙（"锁区间"），其他事务无法插入
### 3. 临键锁（Next-Key Lock）

| 加锁条件                    | 说明                        |
| :---------------------- | :------------------------ |
| 非唯一索引等值查询，记录**存在**      | Next-Key Lock（记录锁 + 右间隙）  |
| 范围查询（`>`、`<`、`BETWEEN`） | 扫描到的每个索引记录加 Next-Key Lock |
### 4. 插入意向锁（Insert Intention Lock）

**加锁条件：**
- 任何 `INSERT` 操作，在插入前对目标间隙加插入意向锁
- **与间隙锁互斥**：若已有事务持有某间隙的间隙锁，其他事务插入该间隙必须等待
- 与另一个插入意向锁**不互斥**（不同事务可同时持有同一间隙的插入意向锁）

## 锁升级（Lock Escalation）
SQL Server、Oracle 有锁升级：当行锁数量超过阈值时，升级为表锁
InnoDB: 不走索引 → 全表每条记录都加间隙锁

## 死锁
所谓死锁：是指两个或两个以上的进程在执行过程中，因争夺资源而造成的一种互相等待的现象，若无外力作用，它们都将无法推进下去。此时称系统处于死锁状态或系统产生了死锁，这些永远在互相等待的进程称为死锁进程。表级锁不会产生死锁。所以解决死锁主要还是针对于最常用的 InnoDB。

死锁的关键在于：两个(或以上)的 Session 加锁的顺序不一致。
