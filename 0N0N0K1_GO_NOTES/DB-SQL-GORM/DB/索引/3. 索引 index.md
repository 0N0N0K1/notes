# 1. 索引种类
## 1.1 B-Tree （默认索引）

```sql
CREATE INDEX <idxName> ON <table>(<colomn>);   -- 默认索引 是 btree
```
>[!tip] 
>1. <  <=  =  >=  >、BETWEEN、IN、IS NULL、LIKE 'abc%'（不带前导通配符）、排序 ORDER BY 时都会使用B-Tree索引加速
>2. 适用几乎所有类型（数字、字符串、时间、布尔…）
>3. 数据量大且重复值多时，PG13+ 的 deduplication 能省很多空间

## 1.2 Hash
```sql
CREATE INDEX <idxName> ON <table> USING hash (<colomn>);
```
>[!tip]
> 只支持 = 等值查询，但比B-Tree更快
## 1.3 GiST（Generalized Search Tree）
```sql
CREATE INDEX  <idxName> ON <table> USING gist (<colomn>);

-- 扩展
CREATE EXTENSION btree_gist;   -- 让 int/text 也能用 GiST（排他约束必需）
```

- 擅长**"非精确匹配"**：范围重叠、几何相交、邻近搜索
- 典型场景：
    - 范围类型（`tstzrange` 时间段重叠）
    - 几何/地理数据（`point`、`box`，配 PostGIS 做空间索引）
    - 排他约束 `EXCLUDE`
    - 近邻查询 `ORDER BY col <-> point '(1,1)'`

## 1.4 SP-GiST（Space-Partitioned GiST）
```sql
CREATE INDEX  <idxName> ON <table> USING spgist (<colomn>);
```

- GiST 的细分类型树结构，适合**空间分区类数据**
- 典型场景：几何、IP 地址（`inet`）、文本前缀（`text_ops`）、四叉树/k-d 树数据
- 日常用得少，知道和 GiST 分工即可
## 1.5 GIN（Generalized Inverted Index）
```sql
CREATE INDEX  <idxName> ON <table> USING gin (<colomn>);
```

- 专为**"一个值里包含多个元素"**的列设计：数组、jsonb、全文检索
- 典型场景：

```sql
tags      text[]              → 查 'WHERE tags @> ''{体育}'''
data      jsonb               → 查 'WHERE data @> ''{"a":1}'''
content   tsvector            → 全文检索（配 to_tsvector）
```

- 更新代价比 btree 大，但检索多值元素极快
    

## 1.6 BRIN（Block Range Index）——大表神器
```sql
CREATE INDEX idx ON t USING brin (created_at) WITH (pages_per_range = 128);
```

- 原理：不存每行的指针，只存每段连续块（默认128页）的 min/max 摘要
- 体积只有 btree 的几十分之一，适合物理有序的大表（时间序、自增 id）
- 场景：亿级日志表按时间范围查询；不适合随机分布数据

# 2. 索引形态
1. 唯一索引 / 唯一约束
```sql
CREATE UNIQUE INDEX idx ON t (email);
-- 或 UNIQUE 约束（带约束名，报错信息友好）
```
 2. 多列（复合）索引
```sql
CREATE INDEX idx ON t (status, created_at);
```

规则：**等值列在前、范围列在后**；`WHERE status='x' ORDER BY created_at` 一条索引搞定

 3. 部分索引（Partial Index）
```sql
CREATE INDEX idx ON orders (user_id) WHERE status = 'pending';
```
- 只索引满足条件的行：体积更小、维护更快、查询必须带同样条件才生效
- 典型：未处理订单、未删除标记、活跃用户

4. 表达式索引
```sql
CREATE INDEX idx ON users (lower(email));
CREATE INDEX idx ON orders ((amount * quantity));
```

- 查询条件写成一样的表达式才能命中：`WHERE lower(email) = 'a@b.com'`

 5. 覆盖索引（INCLUDE）
```sql
CREATE INDEX idx ON users (email) INCLUDE (name, created_at);
```

- 索引里带上查询需要的列，直接 index-only scan，不回表
    

 6. 降序/混合排序
```sql
CREATE INDEX idx ON t (created_at DESC, id ASC);
```
- 匹配 `ORDER BY created_at DESC, id ASC` 的查询
