# 索引结构
## B Tree
- 每个节点都挂数据
- 叶子节点没有链接
- 非叶子节点没有在叶子节点做备份
![[扫描文件_20260926_154624.jpg]]

## B+Tree
- 只有叶子节点挂数据
- 非叶子节点在叶子节点做备份
- 所有叶子节点链接起来（单向/双向/循环）![[扫描文件_20260926_154624(1).jpg]]
## MySQL采用B+Tree作索引
![[Pasted image 20260926160155.png]]
- 叶子间形成双向环形链表
- 一个节点大小为一页16KB

优点
- 有双向环链表，比hash多支持范围查询
- 非叶子节点不挂载数据，比B Tree的非叶子节点能存更多指针，数高更小
# 索引分类
聚簇索引：主键字段建立的索引，叶子节点挂行数据（索引组织表）（优先在主键产生，其次自己创建隐藏字段主键）
二级索引：非主键字段建立的索引，叶子节点挂主键ID值

# 索引分裂、合并、重组
## 分裂
原因：当前索引页空间不足后插入一条数据
顺序插入：分配新页，由于新记录值比之前的大，只将新记录插入新页，旧记录不用动
![[Pasted image 20260926165233.png]]
随机插入：
1. 页分裂(Page Split):申请新页,把原页数据拆一半过去(50/50 分裂)
2. 原页出现 半空状态,页与页之间物理位置不连续 → 碎片
![[Pasted image 20260926170116.png]]
## 页合并
DELETE 或 UPDATE 导致页中记录减少,当页的使用率低于 **MERGE_THRESHOLD(默认 50%)** 时,InnoDB 尝试把这个页和相邻页 **合并**:只在 **相邻页能容纳合并后数据** 时才合并,否则不动作
```plain
页A [3条记录,15%满] + 页B [20条记录,65%满]  →  合并成一个页 [23条,80%满]
空出来的页A 还给表空间复用
```

|     | 说明                        |
| :-- | :------------------------ |
| 好处  | 回收半空页、减少碎片、让范围扫描更紧凑       |
| 代价  | 合并本身要移动数据、改链表、产生 redo log |

## 索引重组

| 方式                            | 原理                      |
| :---------------------------- | :---------------------- |
| `OPTIMIZE TABLE t`            | 等价于重建 + 更新统计信息 + 释放未用空间 |
| `ALTER TABLE t ENGINE=InnoDB` | 重建整个表(所有索引重建,数据按主键顺序重写) |
| `ALTER TABLE t FORCE`         | 同上,8.0 中 OPTIMIZE 的背后实现 |

- 数据页按主键顺序 物理重排,空洞被消除,页利用率回到高位
- 索引树层高可能降低
- 统计信息重新采集,优化器选择更准确
- ibd 文件缩小
