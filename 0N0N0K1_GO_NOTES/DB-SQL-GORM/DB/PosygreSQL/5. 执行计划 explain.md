## 命令格式
```
EXPLAIN  [选项 [, ...]]  SQL语句;
```

| 选项         | 作用                                              |
| ---------- | ----------------------------------------------- |
| `ANALYZE`  | ==真正执行语句==，返回实际时间、行数、loops; ==写操作要放在事务并回滚==     |
| `VERBOSE`  | 输出更多信息，如输出列、表达式、schema 名                        |
| `COSTS`    | 显示估算成本，默认on                                     |
| `BUFFERS`  | 显示共享块、临时块读写情况                                   |
| `WAL`      | 显示 WAL 使用情况                                     |
| `TIMING`   | 是否统计实际时间，默认开启；设为 off 可降低 ANALYZE 开销             |
| `SUMMARY`  | 显示 Planning Time / Execution Time，ANALYZE 时默认开启 |
| `SETTINGS` | 显示影响计划的非默认参数                                    |
| `FORMAT`   | 输出格式：`TEXT`、`XML`、`JSON`、`YAML`                 |
## 节点结构

返回结果为树状结构（缩进加->表示子节点），执行顺序由子到父
```plain
节点类型  (cost=启动成本..总成本 rows=估算行数 width=行平均宽度)(actual time=启动耗时..总耗时 rows=实际行数 loops=执行次数)
Filter: (过滤条件)
Rows Removed by Filter: 过滤行数
Buffers: shared hit=缓存命中数 read=磁盘读取数
```
actual time以毫秒为单位，而 cost 无量纲

cost 根据具体公式计算出：包含多方面因素（cpu、io、扫描元组树、扫描page数、索引数高度、配置的相关计算参数……）
## 节点类型 

| 节点                                              | 含义                                                                                                                                                                            |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seq Scan                                    | 从表文件的第一个数据页读到最后一个，逐行检查是否满足条件                                                                                                                                                  |
| Index Scan                                  | B-tree 索引定位到符合条件的行，再按索引里存的 ctid 回表取整行数据                                                                                                                                       |
| Index Only Scan                             | 查询需要的列全部在索引里，不需要回表，只扫索引                                                                                                                                                       |
| Bitmap Index Scan + Bitmap Heap Scan        | 1. Bitmap Index Scan：走索引，把命中的行位置按数据页为单位构建成一个位图<br>2. Bitmap Heap Scan：按页号顺序读表，每页只读一次，再 Recheck 具体哪行符合条件                                                                       |
| TID Scan                                    | 直接按 ctid 定位                                                                                                                                                                   |
| CTE Scan / Subquery Scan                    | CTE 执行一次，结果落内存/临时文件，之后 CTE Scan 扫描这份快照                                                                                                                                        |
| Sort                                        | 排序，常见于 ORDER BY / DISTINCT / GROUP BY。<br>     quicksort Memory: ...kB内存排序，最快<br>     external sort Disk: ...kB临时文件排序（超 work_mem）<br>     top-N heapsortLIMIT N 的堆排序，只保留前 N 个 |
| Aggregate /  HashAggregate / GroupAggregate | 聚合                                                                                                                                                                            |
| Gather (Parallel...) / Parallel Seq Scan    | 并行查询，max_parallel_workers_per_gather 控制                                                                                                                                       |
| Limit                                       | 会让下游节点提前终止                                                                                                                                                                    |
| Materialize                                 | 物化中间结果                                                                                                                                                                        |
| Append                                      | UNION ALL 或分区表扫描                                                                                                                                                              |
| Memoize                                     | 缓存嵌套循环内层重复查询结果                                                                                                                                                                |
| Incremental Sort                            | 输入已按排序键的前缀有序只需在每个 a 组内部排序 b，避免全局排序                                                                                                                                            |
| LockRows                                    | FOR UPDATE 加锁                                                                                                                                                                 |
两张表 Join 节点

| 节点                    | 算法                                                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Nested Loop（嵌套循环） | 外层表每取一行，内层表找一遍匹配行。时间复杂度 O(M×N)。                                                                                      |
| Hash Join         | 1. Build 阶段：把小表（build side）读一遍，在内存建哈希表（以 join key 为键）<br>2. Probe 阶段：顺序扫大表（probe side），每行算哈希值去表里探测匹配 |
| Merge Join        | 两边都按 join key 排好序，各用一只指针归并前进                                                                                     |
