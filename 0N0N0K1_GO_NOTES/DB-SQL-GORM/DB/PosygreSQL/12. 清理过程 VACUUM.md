>[!tip] VACUUM命令用于回收死元组（dead tuples）占用的页空间与索引、冻结过旧元组事务标识t_infomask中置冻结txid=2、更新FSM与VM、移除不需要的CLOG、更新统计数据与系统视图
 

在PostgreSQL中，被删除或更新废弃不再被引用的元组并没有在物理上从它们的表中移除，将存在直到VACUUM被执行，==导致表与索引膨胀==
```sql
VACUUM [ FULL ] [ FREEZE ] [ VERBOSE ] ANALYZE [ table_name ]
```
FULL选项会执行更广泛的处理，包括跨块移动行以压缩表，但会锁定整个表
FREEZE选项用于冻结旧的事务ID，防止事务ID包裹问题
VERBOSE选项会显示详细的清理工作报告 
ANALYZE选项用于更新查询优化器的统计信息 
table_name是指要清理的表的名称，未加则VACUUM会处理当前数据库中的所有表

1. VACUUM概述:
     - 参考VM文件回收表中的死元组，将这些死数据标记为可重用，将来插入新数据时可以重用空间
     - 冻结旧元组：可以分两种模式
         惰性模式：计算出需要冻结的txid边界，但会跳过全可见页面，导致其中无法冻结
         迫切模式：会扫描所有页及其元组，不会漏冻结，但效率低
     - ==操作过程不会锁定表==，因此可以与其他操作并行进行
2. VACUUM FULL:
     - 不仅执行常规VACUUM的功能，还会重新组织表中的数据，填充已删除的元组的空间，避免页面出现碎片，重建索引并更新FSM、VM、统计信息与系统视图
     - ==操作过程会锁定表==，因此在执行期间不能对表进行访问；过程中会占用近两倍于表的空间

autoVacuum功能:
    autovacuum是一个自动执行VACUUM和ANALYZE命令的系统辅助进程它的主要目的是:
    - 回收被标识为删除状态的空间，确保数据库性能不会因为数据膨胀而下降
    - 更新表的统计信息
    - 防止事务ID回卷

```
 autovacuum：控制是否启动系统自动清理功能，默认值为on
 autovacuum_max_workers：设置系统自动清理工作进程的最大数量
 autovacuum_naptime：设置两次系统自动清理操作之间的间隔时间
 autovacuum_vacuum_threshold和 autovacuum_analyze_threshold：设置当表上被更新的元组数的阈值，超过这些阈值时分别需要执行vacuum和analyze
 autovacuum_vacuum_scale_factor和autovacuum_analyze_scale_factor：设置表大小的缩放系数
 autovacuum_freeze_max_age：设置需要强制对数据库进行清理的XID上限值
```
