>[!tip]
>1. 索引与数据分离
>     - 主键、唯一约束都靠**独立索引**维护，数据不按主键组织 物理无序
>     - 所有索引（包括主键）叶子存的是 ctid 指针，不是主键值
>     - 查询走索引 = 索引页定位 → 拿 ctid → 回表读堆页
>     - 索引与堆是两套独立的页结构、独立的文件
>2. 页面自治
>     - 每个 8KB 页独立管理：头部 + 行指针数组 + tuple 区
>     - 页间无链接，全表扫描 = 顺序读所有页
>     - TOAST（超大属性存储技术）：由于页面大小固定且不允许元组跨页存储，当字段值>2kb，TOAST 会先尝试压缩，如果仍然太大，则将其拆分并存储到单独的 TOAST 表中
>
## 结构层次
![[Pasted image 20260924211553.png]]
1. 每个数据库都会分配一个oid
2. 数据库中每个表/索引也会分配一个oid,当表数据大于1GB（默认）会分段——创建/oid.1, /oid.2以此类推的新文件存放数据
3. 辅助存储文件: 
    - 空闲空间映射文件（FreeSpaceMap    .fsm）：每个堆表和索引都有一个 FSM 文件，用于提供页面中的可用空间
    - 可见性映射文件（.VM）：用于提供各页面是否包含不可见/死元组
4. 在PG中表、索引、TOAST表都称作关系, 数据文件、可见性映射文件、空闲空间映射文件称作关系的分支(fork)

数据文件包括堆表文件，索引文件，.fsm文件, .vm文件 内部由固定长（默认8kb）的页构成
表的页面page包含了五部分：
1. 特殊空间
    供索引使用的特殊数据区域
2. 堆元组（heap tuples）
    堆元组就是数据，从页面底部特殊空间结束处开始依序堆叠
3. 空闲空间/空洞
4. 行指针（line pointer）
    每个行指针占4个字节，保存着指向堆元组的指针。
    它们也被称为项目指针（item pointer）。
    行指针简单地组织为一个数组，扮演了元组索引的角色。每个索引项从1开始依次编号，称为偏移号（offset number）。
    当向页面中添加新元组时，一个相应的新行指针也会被放入数组中，并指向新添加的元组
5. 首部数据（header data）
    页面的起始位置分配了由结构PageHeaderData定义的首部数据。它的大小为24个字节，包含关于页面的元数据。该结构的主要成员变量为：

| page header 字段      | 作用                               |
| ------------------- | -------------------------------- |
| pd_lsn              | 该页上次变更XLOG记录对应的LSN,与WAL相关        |
| pd_checksum         | 该页的校验和                           |
| pd_flags            | 当前page 的一些flag信息，是否有空,其元组是否对外可见等 |
| pd_lower            | 该页空闲空间的起始偏移位置的指针                 |
| pd_upper            | 该页空闲空间的结束偏移位置的指针                 |
| pd_special          | 该页特殊空间的起始偏移位置的指针                 |
| pd_pagesize_version | 该页大小和版本信息                        |
| pd_prune_xid        | 该页可以回收的最老的元组XID(事务ID)            |

元组标识符 TID/ctid:   (pageID，行指针偏移号)
堆元组（heap tuples）结构：

| tuple字段                | 作用                                                              |
| ---------------------- | --------------------------------------------------------------- |
| len                    | 整个tuple header-data + data-area 的长度                             |
| t_self                 | 标识当前 tuple 所处的 page 位置（page的block-number 以及 page内的offset）       |
| tableOid               | 当前tuple所处的表的唯一标识                                                |
| HeapTupleHeader t_data | 保存整个tuple的 header 关键信息。其内部的字段与 pg 要是实现的事务语义强相关                  |
| t_xmin                 | 标识插入元组时的事务id                                                    |
| t_xmax                 | 标识对当前元组进行更新/删除 时的事务id, 如果 t_xmax 被设置为0，则标识没有事务操作对该元素进行 更新和删除    |
| t_cid                  | 保存命令标识（command id, cid），cid意思是在当前事务中，执行当前命令之前执行了多少SQL命令，从零开始计数  |
| t_xvac                 | 标识执行 vaccum full 操作的id                                          |
| t_ctid                 | 唯一标识一个元组，如果当前元组被更新或者删除，则t_ctid 则会被更新为最新的元素的t_ctid               |
| t_infomask2            | 标识当前元组有多少列                                                      |
| t_infomask             | 存储了元组的属性flag信息，比如 当前元组是否有空列， 是否有变长的列，该元组是否冻结，以及xmin事务状态hint bit |
| t_hoff                 | 标识整个header + 后面的bitmap的占用偏移，方便上层利用t_hoff 计算实际的data_area 数据      |
| t_bits                 | 空值位图，有null值，这里会记录，是一个变长的 bitmap数组，用来标识当前元组某一列是否为空               |
| data_area              | 元组的数据区域                                                         |

## 元组增删改流程

- insert
![[Pasted image 20260924233854.png]]
- update 
不会原地修改；旧纪录修改t_xmax为新事务id, t_ctid指向新记录的位置；新记录与插入类似但t_cid要记录当前命令之前执行了多少SQL命令，从零开始计数

HOT（heap only tuple）特性: 
当新元组与老元组再同一页面时
没有HOT时表元组与索引元组中均要插入一条新数据,索引再分别指向两条数据
有HOT时仅表元组中插入一条新数据，索引不变，老元组t_ctid指向新元组(避免了改变索引的开销 )
