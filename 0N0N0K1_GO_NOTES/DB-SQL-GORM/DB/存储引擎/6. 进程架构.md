![[Pasted image 20260924221145.png]]

1. Postmaster 服务器主进程
    pgsql启动时，产生 Postmatster 进程即服务器进程，监听5432端口
    负责启动其他后台进程、分配共享内存、等待客户端连接并为其启动用户后端进程

2. backend 用户后端进程
    与客户端TCP连接通信，处理客户端发出的命令，连接断开时终止
    一个连接只能操作一个数据库，连接时指定

3. Bgwriter 后台写进程
    - 定期把脏数据从内存缓冲区刷出到磁盘中，减少查询时的阻塞
    - PG在定期作CheckPoint时需要把所有脏页写出到磁盘
    通过BgWriter预先写出一些脏页，可以减少设置CheckPoint时要进行的IO操作，使系统的IO负载趋向平稳

 4. PgArch 进程
    负责将WAL日志归档
    （archive_mode：可选择为off（关闭）、on（启动）和always（总是开启）; 
     WAL日志会被循环使用，过去的WAL日志会被新产生的日志覆盖; 
     归档日志的作用是为了数据库能够使用全量备份和备份后产生的归档日志，从而让数据库回到过去的任一时间点）
     
 5. PgStat统计数据收集进程
    用来收集数据库运行期间的统计信息，如表的增删改次数，数据块的个数，索引的变化等等。收集统计信息主要是为了让优化器做出正确的判断，选择最佳的执行计划

6. AutoVacuum 进程
    周期性启动系统自动清理

7. WalWriter 进程
    周期性将WAL缓冲区数据刷入WAL文件持久化

8. Checkpoint 进程
    负责处理检查点

# backend 用户后端进程

包含如下5个子系统
1. 解析器： 根据SQL语句产生解析语法树（parse tree）
![[7a24c5538dbc4f6996f27041d43e18b7.jpg]]
2. 分析器： 对语法树进行分析生成查询树（query tree）
![[80d62df13cd64f39752f9cbae525c55a.jpg]]
3. 重写器： 按照系统规则对查询树改写
![[ee37560e982917030523ae12ae3a660e.jpg]]
4. 计划器： 基于查询树生成执行效率较优的计划树（plan tree）
    - 可以通过explain命令进行查看
5. 执行器：按照计划树的顺序执行访问，执行相应计划
