## 插入缓存
解决问题：非唯一二级索引的插入是一次磁盘随机读写，代价很高，通过插入缓存减轻IO负担

- 当插入/修改的数据涉及非唯一二级索引，且目标索引页不在 Buffer Pool 中时，InnoDB ==不立即读磁盘修改==，而是把操作记录到内存中的 Insert Buffer
- 等该索引页之后被读入内存时，再执行 merge 合并；后台master线程也会定期合并、数据库关闭前强制合并

## redo重做日志缓冲区
WAL（Write-Ahead Logging）：日志先行。事务提交时只保证日志**顺序写**到磁盘，数据页可以异步慢慢刷盘
![[Pasted image 20260926145511.png|487]]
## 双写缓冲区

- 关键问题：InnoDB 数据页大小是 **16KB**，意味着写一页需要多 I/O。写到中间时宕机磁盘上这页就是一半新一半旧的撕裂页（torn page），而redo 只记录页的增量修改，不记录整页,崩溃恢复时出现错误

脏页刷新流程：
1. 脏页先从 buffer pool ==同步顺序IO写入== doublewrite buffer（磁盘文件）
2. 再把脏页  ==异步IO写入==   各自的数据文件（.ibd）中

# 后台核心线程
![[Pasted image 20260926152334.png]]
## 1. master 主线程
数据库启动时激活
- 每秒把日志缓冲(log buffer)刷新到磁盘
- 刷新脏数据页到磁盘
- 合并插入缓冲
- 回收 undo 页
- 产生 checkpoint(检查点)
## 2. IO 线程
负责处理 **AIO(异步 IO)请求的回调** 和各类异步读写

| 线程                       | 默认数量 | 职责                |
| ------------------------ | ---- | ----------------- |
| **read thread**          | 4    | 数据页的预读和随机读取       |
| **write thread**         | 4    | 数据页的写回(刷脏页)       |
| **insert buffer thread** | 1    | 合并写 insert buffer |
| **log thread**           | 1    | 刷新 redo log 到磁盘   |
## 3. Purge 清理线程

事务提交后,其 undo log 不能被立即删除,因为可能有其他事务需要通过 undo 构建旧版本数据(MVCC)
这些不再需要的 undo 由 Purge Thread 异步回收
## 4.Page Cleaner 脏页刷新线程

**MySQL 5.6 引入**,专职负责把缓冲池中的脏页刷新到磁盘。

## 5. Redo log flush redo刷盘线程
5.8+/8.0

# 文件组织
![[Pasted image 20260926152354.png]]
### 1. 系统表空间(System Tablespace)
- 文件:`ibdata1
- 存放内容:
    - 数据字典(表、索引元信息)
    - 双写缓冲(Doublewrite Buffer)
    - Change Buffer
    - Redo Log
        - `ib_logfile0` / `ib_logfile1
        - 记录物理日志,用于崩溃恢复

### 2. 独立表空间(File-Per-Table Tablespace)
- 每张表对应一个独立文件:`数据库名/表名.ibd`
    - 删表/删库可以直接 回收磁盘空间
    - 支持单表备份、传输表空间(Transportable Tablespace)
    - 便于监控每张表的大小
- 文件内包含:表的数据 + 索引 + insert buffer bitmap
### 3. 通用表空间(General Tablespace)

- 多张表可以放进 **同一个表空间文件**,由用户显式创建和管理
- 用途:在磁盘间平衡 IO、把多个小表合并管理
### 4. Undo 表空间(Undo Tablespace)

- 文件:`undo_001`、`undo_002` 等
- 存放 undo log,用于事务回滚和 MVCC
### 5. 临时表空间(Temporary Tablespace)

- 文件:`ibtmp1`
- 存放用户创建的临时表、内部临时表(排序、group by 溢出)
- 可配置大小上限,防止磁盘被撑爆:

![[Pasted image 20260926153439.png]]
```plain
表空间(Tablespace)
 └── 段(Segment)
      └── 区(Extent,1MB,连续64个页)
           └── 页(Page,默认16KB)
                └── 行(Row)
```

| 层级        | 大小         | 说明                   |
| :-------- | :--------- | :------------------- |
| 页 Page    | 16KB(默认)   | InnoDB 最小读写单元        |
| 区 Extent  | 1MB = 64 页 | 空间分配单位,保证物理连续        |
| 段 Segment | 动态         | 数据段(叶子)、索引段(非叶子)、回滚段 |
| 表空间       | 动态         | 顶层容器                 |
