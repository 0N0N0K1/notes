# 1. 逃逸分析

Go 编译器在==**编译阶段**==
分析判断一个变量的引用是否会“逃逸”出当前函数的作用域即**函数返回后不再被==引用**==
决定变量是分配在==**[[堆栈]]**==上

# 2. 查看逃逸分析结果

```bash
go build -gcflags="-m" main.go      # 查看逃逸决策
go build -gcflags="-m -m" main.go   # 更详细，包含决策原因链
```

典型输出：

```plain
./main.go:5:2: u escapes to heap: returned by newUser()
./main.go:5:2: moved to heap: u
./main.go:8:6: newUser() ... argument does not escape
```

关键词含义：

|输出|含义|
|:--|:--|
|`escapes to heap`|逃逸到堆|
|`does not escape`|留在栈上|
|`moved to heap: X too large`|对象过大被移到堆|
|`leaking param`|参数被“泄漏”（如赋给全局、被闭包捕获、存入返回结构体）|
# 3. 典型逃逸现象

## 3.1. 返回局部变量的指针

即使 `u` 是局部变量，因为指针被返回，它必须存活到函数之外 → 堆。
```go
func newUser() *User {
    u := User{Name: "a"} // u 逃逸到堆：指针被返回，函数结束后仍可能被用
    return &u
}
```

## 3.2. 局部变量被闭包捕获，且闭包逃逸

一旦[[闭包]]被返回、存入结构体、交给 goroutine，捕获变量必然逃逸。
```go
func counter() func() int {
    n := 0        // n 逃逸：被返回的闭包捕获
    return func() int {
        n++
        return n
    }
}
```



## 3.3. 变量被存入全局变量 / 被跨 goroutine 共享

传到 channel / 全局变量 的指针、切片，接收方可能是其他 goroutine，同样会逃逸。
```go
var cache map[string]*User

func save(u *User,name string) {

    cache[u.Name] = u // u 逃逸：生命周期超出函数
    
    MyChan<-&name  // name 逃逸
}
```

## 3.4. 接口装箱（interface{} 赋值）

把具体类型赋给接口，通常需要把值拷贝到堆上再装箱（因为要拿到稳定指针）
每个 `Printf` 参数（包括 `%d` 的值参数）都要 spill + 装箱，全部流向 `{heap} ← *fmt.a`。
```go
func f() {
    x := 42
    fmt.Println(x) // x 逃逸：传给 ...interface{} 需要装箱
}
```

## 3.5. 运行时才能确定大小的分配

```go
func makeSlice(n int) []byte {
    return make([]byte, n) // n 非编译期常量 → 底层数组在堆
}
```

## 3.6. 变量过大或栈帧相关限制

局部数组/结构体过大、参数过多时，编译器可能把它们移到堆上（如输出里出现 "too large for stack" / "moved to heap: ... too large"）。

## 3.7. `append` 导致扩容

```go
s := make([]int, 0, 4) // 可能栈上
s = append(s, 1, 2, 3, 4, 5) // 扩容 → 新底层数组在堆
```
