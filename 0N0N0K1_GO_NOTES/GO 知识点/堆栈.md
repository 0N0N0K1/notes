# 一、本质区别

- **栈**：一块**后进先出**的内存区域，由编译器自动管理。函数调用 = 压入一个栈帧，函数返回 = 弹出栈帧。**生命周期由代码结构静态决定**。
    
- **堆**：一块**自由申请、自由释放**的内存池，由运行时（Go 中是 GC）管理。**生命周期由程序的实际引用关系动态决定**。
    

同一个变量放哪，决定权在 Go 里不在程序员手里，而在编译器的[[逃逸]]分析

# 二、进程地址空间中的位置

典型 64 位进程布局（从高位到低位）：

```plain
高地址 ┌─────────────────┐
      │ 栈 Stack         │ ← 向下增长，每个 goroutine 一块
      │    ↓             │
      │ （空闲）          │
      │    ↑             │
      │ 堆  Heap         │ ← 向上增长，Go 运行时整体管理
      │  .bss / .data    │ ← 全局变量、静态数据
      │  .text           │
低地址 └─────────────────┘
```

# 三、核心对比表


| 维度    | 栈                           | 堆                              |
| :---- | :-------------------------- | :----------------------------- |
| 分配方式  | 移动栈指针（SP），一条指令              | 走分配器（mcache→mcentral→mheap），多步 |
| 回收方式  | ==函数返回，SP 回移，立即"失效"==       | ==GC 三色标记，延迟回收==               |
| 分配成本  | ≈ 零                         | 有锁（虽已大量无锁化）、位图查找、span 管理       |
| 生命周期  | 编译期可确定                      | 运行期才能确定                        |
| 内存连续性 | 连续，紧挨调用帧                    | 离散，按 span（8KB 页组）管理            |
| GC 参与 | **不参与**：不扫描、不标记、不回收         | 全程参与：扫描、标记、清扫                  |
| 大小限制  | 小（goroutine 栈最小 2KB，最大 1GB） | 受虚拟内存和 GOGC 约束                 |
| 典型内容  | 局部变量、函数参数/返回值、调用现场          | 逃逸变量、全局数据、容器底层数组、接口装箱          |

# 四、Go 的栈：goroutine 栈

这是 Go 区别于 C/Java 的关键设计：

**1. 独立且轻量**。每个 goroutine 有自己的栈，初始极小（KB 级，老版本 8KB，近年实现约 2KB 起步），按需**连续扩容**（翻倍增长），上限 1GB。
对比：一个 C 线程栈通常 2~8MB 固定——这就是为什么 Go 能开几十万个 goroutine。

**2. 连续栈，非分段**。早期 Go 用分段栈（函数调用频繁时 split stack 开销大），Go 1.3 起改为连续栈：空间不够时分配一块更大的连续内存，把旧栈**整体拷贝**过去，并修正所有指向旧栈的指针（这项工作由运行时配合编译器生成的栈指针调整表完成）。

**3. 栈帧内容**：返回地址、调用者 BP、局部变量、参数与返回值空间。所有内容的生命周期严格绑定在调用栈上。

**4. 栈与 GC 的关系**：Go 的 GC **不扫描栈**。并发标记开始时，栈被当作"根"整体快照为黑色；栈上存指针不会加重标记负担。这是栈分配几乎零成本的另一半原因——不仅分配免费，**后续所有 GC 成本也为零**。

# 六、栈轻堆重

1. ==**缓存局部性**==：栈上数据（连续的调用帧）几乎必然落在热缓存行里；堆对象散落在各处 span，访问更易 cache miss。

2. **==成本==**：
```plain
堆分配的成本链：
  分配:  mcache 查找 + 位图标记 + span 记账（无锁但仍多步）
  之后:  该对象成为 GC 图的节点 → 每次 GC 被扫描、标记
  回收:  等 GC 三色标记到它 → 清扫归还 span
====堆分配的成本大头不在"分配"那一刻，而在它之后的整个生命周期里持续给 GC 交税======

栈分配的成本链：
  分配: SP -= size（一条减法指令）
  回收: 函数返回时 SP 回移（零成本）
  GC:   完全不感知这个对象

```


# 七、栈上空指针问题

C/C++ 里经典的 bug 是返回局部变量地址（悬垂指针）。Go 的答案是**编译期强制**[[逃逸]]：

```go
func f() *int {
    x := 42
    return &x   // 编译器检测到 x 的引用逃出作用域
}               // → x 不在栈上分配，直接在堆上分配（逃逸）
```
