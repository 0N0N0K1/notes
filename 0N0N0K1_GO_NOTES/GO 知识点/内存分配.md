Go 的内存分配器脱胎于 Google 的 **TCMalloc（Thread-Caching Malloc）**，核心思想是：**多级缓存 + 按大小分级 + 无锁化**。

三层结构的目的：
1. 细化锁
2. 一次申请缓存，多次复用
3. 消除外部碎片

# 1.核心概念
## 1.0 page

操作系统是按page管理内存的，同样Go语言也是也是按page为内存单元
page为8KB
## 1.1 mspan与spanclass

1. 内存管理的最小/基本单元
2. 由连续page组成
3. 根据自身大小与分配对象大小分为不同spanclass
4. 相同 sizeclass 的 mspan 通过链表组织，挂在 mcache / mcentral / mheap 下
5. 基于freeindex、allocBits 、gcmarkBits 管理
![[Pasted image 20260914165704.png]]
```go
type mspan struct {
    next *mspan     // next span in list, or nil if none
    prev *mspan     // previous span in list, or nil if none

    startAddr uintptr // address of first byte of span aka s.base()
    npages    uintptr // number of pages in span
    //......
    freeindex uintptr
    //......
    allocCount  uint16        // number of allocated objects
    spanclass   spanClass     // size class and noscan (uint8)
    state       mSpanStateBox // mSpanInUse etc; accessed atomically (get/set methods)
    elemsize    uintptr       // computed from sizeclass or from npages
}
```
spanclass：
```plain
class 0 是特殊类：它是大对象"标记（>32KB 的对象 sizeclass 记为 0）
// class  bytes/obj  bytes/span  objects  tail waste  max waste
//     1          8        4096      512           0     87.50%
//     2         16        4096      256           0     43.76%
//     3         24        4096      170           0     29.24%
//    ...
//    67      32768       32768        1           0    12.50%
```
## 1.2 mcache

1. 每个P一个，不是 M，避免了线程切换带来的缓存失效
2. goroutine 分配内存时当前 P 的 mcache 直接服务，天然无锁
3. 持有每个 sizeclass 一个 mspan
4. 具有 tiny allocator 处理 tiny 对象（小于 16B 且不含指针）分配
```go
type mcache struct {
    // Tiny allocator
    tiny       uintptr   // 当前 tiny block 的起始地址
    tinyoffset uintptr   // 在 tiny block 内的偏移
    tinyAllocs uintptr   // 累计从 tiny 分配的对象数

    // mcache 缓存每种 spanClass span各一个
    alloc [numSpanClasses]*mspan   // 136 个槽位

    // 栈缓存 ---
    stackcache [numStackOrders]stackfreelist

    // 清扫代际标记 
    flushGen uint32
}
```
## 1.3 mcentral

1. 一个mcentral通过链表存放一种spanclass的mspan，noscan/scan分开，共68 size class × scan/noscan个
2. 每组两个链表
    - partial：有空闲槽位的 span
    - full：已用尽、或 GC 后暂时全空闲待回收的 span
3. 需要加锁，但锁粒度细、竞争小
```go
type mcentral struct {
    lock mutex 
    _         sys.NotInHeap   // GC 不扫描此结构本身
    spanclass spanClass        // 本 central 服务的规格

    partial [2]spanSet   // 有空闲对象的 span 集合
    full    [2]spanSet   // 无空闲对象的 span 集合
}
```
## 1.4 mheap
1. 全局唯一
2. 从 OS 申请/归还虚拟内存（arena）
3.  基于 radix tree 页索引寻找空闲页
4. 基于 heapArena 管理 free 页

```go
type mheap struct {
    lock mutex              // 全局锁，大对象分配、页分配时持有
    
    // 页分配器
    pages pageAlloc         // 基于 radix tree 的页索引

    // Arena 索引
    arenas [1 << arenaL1Bits]*[1 << arenaL2Bits]*heapArena
    // 每个 heapArena 管理 64MB
    // 理论堆上限: 2^22 * 64MB = 256TB

    // 中心缓存数组 
    // 136 个 mcentral，pad 防止 false sharing
    central [numSpanClasses]struct {
        mcentral mcentral
        pad      [cpu.CacheLinePadSize - unsafe.Sizeof(mcentral{})%cpu.CacheLinePadSize]byte
    }
    

    // span 索引 
    allspans []*mspan        // 所有 mspan 的指针（用于 GC 和调试）

    //  清扫代际
    sweepgen uint32          // 全局 sweep generation，每轮 GC +2

    // 
}

```


## 1.5 heapArena


1. Arena 是 OS 申请虚拟内存的单位（包含 8192 * page=64MB）
2. 记录 page 到 mspan 映射
3. 使用位图记录，辅助GC
```go
type heapArena struct {
    spans        [8192]*mspan      // 页 → span 的映射表
    pageInUse    [1024]uint8       // 页占用位图
    pageMarks    [1024]uint8       // 页标记位图（GC 本轮是否扫到存活对象）
    zeroedBase   uintptr           // 从未用过、天然为零的分界线
}
```
## 1.6  radix tree

 辅助寻找连续空闲页
```plain
从 root（L0）开始，看子树的最长连续
   → 用 pallocSum.max 快速排除不可能的分支
   
沿着满足条件的分支一路向下（L1 → L2 → L3）

 到达叶子（chunk，512 页 = 4MB），查位图：
   chunk 的 bitmap 每 bit 代表一页，1=已用，0=空闲
   
在 bitmap 里找连续的 0
   → 用内置的 bits.TrailingZeros64 等指令加速
   
定位到 chunk a，位图扫描找到起始bit b,把对应 bit 置 1，然后向上更新 summary
找到起始页号addr=a*512+b，
 
属于哪个 arena？
   arenaIdx = addr ÷ 64MB 
   → arenas[0][76] → *heapArena

arena 内哪一页？
   页号 = (addr % 64MB) ÷ 8KB 
   → heapArena.spans[68] 登记新 mspan

组装 mspan
   startAddr = addr, npages = 5, sizeclass = ...
   → 挂到 mcentral / mcache
   
```

## 1.7 scan/noscan

scan / noscan 是 mspan 的类别，本质由==对象类型是否可能包含指针决定==：

- scan：该 span 里的对象可能含指针，[[GC]] 标记阶段必须扫描对象内部，找出并标记它引用的其他对象。
- noscan：该 span 里的对象保证不含指针，[[GC]] 不需要扫描对象内部，只标记这些对象本身即可。
