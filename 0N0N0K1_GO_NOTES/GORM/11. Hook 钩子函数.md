# 1. 生命周期与 Hook 执行顺序

1. 创建（Create）
```plain
开始事务
 → BeforeSave
 → BeforeCreate
 → （关联前的 save）
 → 插入记录
 → （关联后的 save）
 → AfterCreate
 → AfterSave
 → 提交（任一步出错则回滚）
```

2.更新（Update）
```plain
开始事务
 → BeforeSave
 → BeforeUpdate
 → （关联前的 save）
 → 更新记录
 → （关联后的 save）
 → AfterUpdate
 → AfterSave
 → 提交或回滚
```

3. 删除（Delete）
```plain
开始事务
 → BeforeDelete
 → 删除记录
 → AfterDelete
 → 提交或回滚
```

4. 查询（Query）
```plain
从 db 加载数据
 → Preload 预加载关联
 → AfterFind
```

# 2. 用法示例

>[!attention]
>1. 钩子是在模型生命周期的关键节点自动执行回调函数，在事务中运行，返回错误会回滚整个操作，==钩子返回错误 = 撤销本次操作：这是安全也是坑==
>2. 注意查询没有事务（读操作不需要），且只有 AfterFind 一个钩子
>3. 钩子里用 `tx` 做新操作时，条件写全，不要假设继承了外层链式条件
>4. 软删除不触发 BeforeDelete/AfterDelete
>5. 钩子里的递归触发： AfterUpdate 里更新同一张表会再次触发钩子 → 死循环，需要用 `tx.Session(&gorm.Session{SkipHooks: true})` 跳过
>6. 批量操作多次触发钩子影响性能，需要钩子逻辑足够轻量，重逻辑放业务层。

**BeforeCreate：填充字段 + 校验**
```go
func (u *User) BeforeCreate(tx *gorm.DB) (err error) {
    u.UUID = uuid.New()        // 自动生成 UUID
    u.CreatedBy = getOperatorFromCtx(tx.Statement.Context)  // 从 ctx 取操作人
    
    if !u.IsValid() {
        return errors.New("can't save invalid data")  // 返回错误 → 中止插入
    }
    return
}
```

**AfterUpdate：级联更新**
```go
// 与用户更新放在同一个事务中
func (u *User) AfterUpdate(tx *gorm.DB) (err error) {
    if u.Confirmed {
        tx.Model(&Address{}).Where("user_id = ?", u.ID).Update("verified", true)
    }
    return
}
```

**AfterFind：填充默认值**
```go
func (u *User) AfterFind(tx *gorm.DB) (err error) {
    if u.MemberShip == "" {
        u.MemberShip = "user"  // 老数据补默认值
    }
    return
}
```
