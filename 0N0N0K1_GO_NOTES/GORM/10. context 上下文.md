
# 1.WithContext（）
之后的链式调用都共享这个 ctx，但只影响这一次链。
```go
// WithContext 链式传入
db.WithContext(ctx).Find(&users)
```

WithContext(ctx) 返回一个新的 * gorm.DB 实例，后续一系列相关操作共享同一个 ctx，事务场景的典型用法
```go
tx := db.WithContext(ctx)
tx.First(&user, 1)                          // 同一个 ctx
tx.Model(&user).Update("role", "admin")     // 同一个 ctx
```

# 2. 超时控制

防止慢查询拖垮服务：
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

users, err := db.WithContext(ctx).Find(&users)
```
ctx 超时 
-> GORM 取消查询
-> 底层数据库驱动收到取消信号 
->MySQL/PostgreSQL 驱动会发送取消请求（kill query），释放连接和锁
->返回的错误 context.DeadlineExceeded

>[!attention] 超时时间是**整个操作的预算**，包括网络往返,要预留足够余量

# 3. 链路追踪
>[!tip]
>1. OpenTelemetry 的 span 通过 ctx 传递，DB 调用自动成为 trace 的一个节点
>
>2. 日志可以看操作对象与操作链路的追踪

# 4. Hooks/Callbacks 中的 Context

**级联取消**：Hook 里的二次命令或者操作也能被外层 ctx 超时控制

Context也可以在 GORM 的Hook/Callbacks中访问。 这使得在这些生命周期事件中可以使用上下文信息

```go
func (u *User) BeforeCreate(tx *gorm.DB) (err error) {  
  ctx := tx.Statement.Context  
  // ...使用ctx做一些你想做的事  
  return  
}
```
