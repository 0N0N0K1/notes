# 1. 简介

RPC（Remote Procedure Call Protocol，远程过程调用协议）
==一种通过网络从远程计算机程序上请求调用存在于远程计算机上的某个对象，就像调用本地应用程序中的对象一样，而不需要了解底层网络技术的协议。==

作用
1. 实现跨进程/语言/系统通信（实现分布式系统，应用服务解耦）
2. 屏蔽底层网络复杂性（传输协议与传输格式）
3. 提高性能，降低延迟（相对于传统用HTTP+JSON实现）

# 2. 调用流程

1. client调用服务
---
（以下对用户透明）
    1. client stub接收到调用后负责将方法、参数等编码进行网络传输并发送到服务端
    2. server stub收到消息后进行解码，调用server的服务
    3. server的服务执行并将结果返回给server stub
    4. server stub将返回结果编码进行网络传输并发送至消费方

---
2. client stub接收到消息并进行解码，返回给client得到最终结果

# 3. IDL与Stub
## IDL（接口定义语言）
IDL 是一种与编程语言无关的接口描述语言，用来**定义服务提供的接口和数据结构**。

作用：
1. 定义服务有哪些方法、方法接受什么参数、返回什么数据
2. 通过工具自动生成各种语言的代码

常见 IDL：

1. Thrift IDL（Apache）
2. Avro IDL
3. CORBA IDL
4. ==Protocol Buffers==
## Stub（存根/桩）
Stub 是由 IDL 工具自动生成的代码，它在**本地充当远程服务的代理**。

两种 Stub：

| 类型          | 位置  | 作用                    |
| ----------- | --- | --------------------- |
| Client Stub | 客户端 | 将本地调用序列化为网络消息发送给服务端   |
| Server Stub | 服务端 | 接收网络消息，反序列化后调用实际的业务方法 |

**Stub 的特点：**

- 对调用方透明，调用 stub 就像调用本地方法一样
- 屏蔽了网络通信、序列化、协议等底层细节
- 由工具从 IDL 自动生成，不需要手写
